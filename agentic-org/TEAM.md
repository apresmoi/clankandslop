# Clank & Slop organization

This is a portable, bounded Spawnfile organization. It does not start until `scripts/check-runtime.mjs` verifies each isolated agent home, host-provisioned CLI login, private root, broker, network policy, and Git policy. Spawnfile owns the public Git workspaces, private sensor volumes, shared edition-state volume, durable Moltnet storage, and secret-backed network bindings. Every agent declares the Daimon Codex subscription CLI engine directly. The model intent belongs to its Spawnfile; verify the compiled runtime and actual turn before claiming which model ran.

AGY remains a future broker target, not a runtime engine in this portable Linux build. Host admission may confirm that the AGY subscription login exists, but its current host authentication cannot be portably staged into the Linux container. No manifest may claim otherwise or silently fall back to AGY.

The Spawnfiles deliberately omit a `policy` override. Daimon reports its workspace sandbox intent as degraded; Spawnfile's public default reports that adapter limitation without treating it as an authorization decision. `check-runtime.mjs` remains the fail-closed admission gate for actual homes, logins, private storage, broker, Moltnet, network, and Git policy.

The root owns one managed Moltnet server with durable SQLite state, bearer admission, private member-written rooms, and no human ingress. Agent, research-service, operator, and observe-only console identities reference distinct runtime secrets; no value is authored into a Spawnfile. The research sensor attaches directly to the cloud `research` room, which remains the single source of newsroom history.

Spawnfile 0.1.17 requires Daimon Grok and AGY agents to omit `execution.model`: Daimon owns their subscription authentication and model selection. Codex agents retain the supported OpenAI target with `auth.method: codex`. `check-runtime.mjs` still blocks launch until host-provisioned isolated CLI homes and login capabilities exist.

Daily lifecycle uses `Europe/Berlin` and never a fixed UTC offset. Reporters wake natively at 13:00 to read their own beat and pitch; Brass runs conference at 13:30 and selects the lineup from those pitches; Spike reviews at 15:00; Ledger settles the desk documents at 15:30; Caslon composes at 16:00; Pressman runs mechanical checks and builds at 16:30, then stages the exact accepted edition by 17:00 for an 18:00 public release clock. Every checkpoint with a named agent owner is a native Spawnfile schedule that actually fires: a checkpoint described only in prose is a checkpoint that never runs. Reporters find their own stories — Brass picks which run and kills the rest, and commissions only what the day is missing. Research is a service: the six reporters and Brass may send `research.request.v1` through `moltnet_send` to `room:research` and receive a bounded `research.answer.v1` containing attributable findings and source URLs inline, with a requester mention. The requesting turn ends; the answer can queue and has no guaranteed arrival time. Other desks use the requester routes in FLOOR.md; they do not send sensor requests themselves. Every downstream activation is an explicit Moltnet message carrying edition and causal artifact references. Production human kickoff, editorial task orchestrators and hidden activation are prohibited. An agent may poll its own bounded asynchronous build job; it does not poll or schedule other agents. Sensor timers and deterministic preparation jobs are services, not Daimon agents.

Durable `edition-state` records are the only recovery authority. Prompts and chat history never reconstruct an edition. Raw research remains in sensor volumes or the private broker. Caslon deterministically composes assigned `PASS` artifacts only; Pressman alone writes one composition-digest-keyed local artifact and one causal `staged` receipt. Publication runs outside the organization: the operator-authorized host job holds the deploy key and pushes the dated edition branch. GitHub Actions checks the content-only diff and exact-head CI, merges the edition PR, and explicitly dispatches website deployment.

The public paper’s established article schema, editorial voice, source rules, page blocks, visual grammar, formula authority, and per-owner boundaries are acceptance criteria. Private pipeline names, browser tooling, credentials, and private paths never enter articles, page copy, or public artifacts.

A mention is the literal token `@<agent-id>` — `@cogsworth`, `@world-scout`. Mentions are the only thing that wakes a peer: a bare name, a role word, or a capitalised label addresses nobody and the assignment is never delivered. Every handoff below that says "mentions" means this exact form.

The active edition is the date in the current wake, or the date in the assignment that woke you. If a Moltnet message names an explicit edition, that edition controls. Otherwise interpret message `created_at` and wake timestamps in `Europe/Berlin`; a previous UTC date can still belong to the current Berlin edition near midnight. A historical message that said "today" governed that historical edition only, never the current one. Cross-day references remain readable evidence when the current task asks for them, but old decisions are not fresh orders.

Production turns use the declared newsroom MCP tools plus `moltnet_read` and `moltnet_send`; test-runtime cognition is never an acceptance surface. Ordinary chat is natural-language coordination. The research service request and answer are the explicit JSON exception in `room:research`; other JSON belongs in durable tool artifacts. FLOOR.md lists each role's concrete operations; RESEARCH_ROUND_TRIP.md is an allowed reference for service messages. Direct Internet research is prohibited for all twelve agents, including browser/search tools, shell HTTP clients and delegation through another CLI or agent. Bounded local reads and declared offline commands remain allowed. A prompt prohibition is not network isolation: runtime egress must be checked independently, and a `CLANK_NETWORK_POLICY_READY` flag is not proof of a blocked request. Do not claim that an attributed sensor finding was personally retrieved or independently verified. Every tool call carries the immutable inbound `event_key` or schedule occurrence so retries converge:

- Klaxon calls `mcp_newsroom_qualify_signal`, then sends a concise human-readable summary to `room:sensor` mentioning every returned selected desk. A private path is provenance only; the natural-language sensor handoff must itself contain the ranked claims, primary URLs, and verification gaps.
- Brass calls `mcp_newsroom_record_assignment` for at least five sourced stories. Only a successful tool response permits commission handoffs: on refusal or error, Brass reports the service problem without reporter mentions and ends the turn. After acceptance, Brass summarizes the lineup in `room:conference` with plain names, then sends each reporter one actionable `@<id>` assignment in `room:assignment`. The lineup preserves the diversity floor, marks exactly one assignment as the day's forecast (`slot: "forecast"`) and names its `dissenter`; the forecast's shape is enforced at `file_article` and the dissenter records the dissent itself with `mcp_newsroom_record_dissent`. `compose_edition` reports both counts and refuses on neither.
- Reporters ground the Record, write in their established byline voice, call `mcp_newsroom_file_article`, and separately call `moltnet_send` to announce the filing in `room:filing` with the edition date, article id, revision, evidence count, and `@spike`; the assigned forecast also mentions its dissenter in that same message. Saving an article or verdict never sends a message, and mentions inside saved notes or a final answer wake nobody. Revisions use a new event key and never overwrite a conflicting durable event. A reporter never types a `dissent` into its own filing — `file_article` refuses one — and records its own dissent or concurrence against a colleague's revision with `mcp_newsroom_record_dissent`, under the identity its MCP process already carries.
- Spike reads every filed article and calls `mcp_newsroom_review_article`. `REVISION_REQUEST` mentions the owner with actionable notes; only `PASS` proceeds. Spike never rewrites reporter prose.
- Ledger calls `mcp_newsroom_file_desk` for `ledger.settlements` and `ledger.worlddesk`, using only formulas and inputs authorized by SYSTEMS.md.
- Caslon calls `mcp_newsroom_file_desk` for `caslon.chrome` and `caslon.weather`, then `lay_pages` and `mcp_newsroom_compose_edition` with the returned `layout_sha256`. The tools produce exactly `front` and `tape` pages plus the union of every `art.map` and `art.hero_map` the day's articles name, and verify that composition matches the baked structure. Composition requires at least five articles, four desk files, matching PASS verdicts, two distinct papers, and the established 2–3 illustration rhythm. Caslon is the sole page-illustration authority: it selects committed maps and glyphs from the permitted archive and catalogue using PAGES.md and ops/ASSETS.md. Reporters may name existing map references under their filing contract; they never invent map bounds, generate an asset, choose a glyph or place a page block. Caslon can also call its private `bake_map` against the installed ETOPO dataset or `bake_glyph` against vetted installed models, selecting their immutable artifact references through `lay_pages`. Image inspection is optional and is never a release gate. Existing reporter map choices remain unchanged. No agent fetches a model or research source.
- Pressman calls `mcp_visual_prepare_release` after Caslon’s composition receipt, starting with `poll: 0` and following the returned `next_poll` and retry interval until complete. The private worker validates the exact composition, builds the site and runs mechanical renderer checks. No agent opens a page or approves an image.
- Pressman calls `mcp_newsroom_stage_release` after the matching successful build. Staging refuses changed composition bytes or failed checks. It never pushes Git or calls a publisher. The host publication job and guarded GitHub edition workflow complete the operator-authorized publication outside the agent runtime.

The visible handoff is `research sensor → Klaxon selected mentions → Brass assignments → reporter filings → Spike verdicts → Ledger settlements → Caslon composition → Pressman mechanical checks/build → Pressman local staging`, and then, outside the organization, `promoted artifact → host-side edition branch → content and CI gates → PR merge → website deployment`. Missing sources, failed validation, a failed build, fewer than five articles, absent desk/page files, or non-PASS prose stops the edition.

The compiler-owned edition state contains `sensor-ledger`, `candidates`, `evidence`, `pinpoint`, `dossiers`, `compose`, `decisions`, and `receipts`. Raw sensor captures stay on the private sensor host; the newsroom reads its pinned private corpus. Newsroom messages carry concise coordination or bounded research findings with source URLs and capture time, never whole raw reports or browser/profile details.
